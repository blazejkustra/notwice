Follow these rules:
- android-no-debuggable: Never hardcode android:debuggable; the build type sets it.
- angular-no-bypass-security: Never bypass Angular sanitization.
- angular-no-native-inner-html: Do not write innerHTML through ElementRef; bind in the template.
- c-no-system: Do not call system(); use exec* with an argument vector.
- commit-body-wrap: Wrap commit message lines at 72 characters.
- commit-no-revert-revert: Do not revert a revert; reapply the change with a new message.
- compose-collect-with-lifecycle: Use collectAsStateWithLifecycle in Compose UI.
- compose-no-privileged: No privileged containers in compose files.
- cpp-no-null-macro: Use nullptr instead of NULL in C++.
- cpp-no-raw-new: Use std::make_unique or std::make_shared instead of raw new.
- css-no-hex-outside-tokens: Use color tokens, not raw hex values.
- css-no-id-selectors: Do not style by id; use classes.
- css-no-outline-none: Never remove focus outlines without a replacement focus style.
- docker-no-latest: Pin base images to a version, never :latest (DL3007).
- erb-no-raw-output: Do not use <%== or raw in ERB on user content.
- express-no-open-cors: Configure CORS with an explicit origin list.
- flask-no-render-template-string: Do not render templates from strings; use template files.
- flutter-no-will-pop-scope: WillPopScope is deprecated; use PopScope.
- gha-no-old-checkout: Use actions/checkout@v4 or newer.
- gha-pin-actions: Pin actions to a tag or SHA, never a branch.
- git-add-by-name: Stage files by name. Never use git add -A, git add --all, git add . or git commit -a.
- go-no-github-com-ghodss-yaml: Replace github.com/ghodss/yaml with sigs.k8s.io/yaml.
- go-no-golang-org-x-exp-slices: Do not import golang.org/x/exp/slices; use the standard slices package.
- go-no-init-functions: No init() functions in library packages.
- go-no-panic-lib: Library packages return errors; they never panic.
- go-skip-needs-reason: t.Skip needs a reason.
- gradle-no-jcenter: jcenter() is shut down; use mavenCentral().
- html-no-inline-handlers: No inline event handler attributes.
- java-no-ecb: Never use ECB mode; use AES/GCM.
- java-no-javax-servlet: Replace javax.servlet with jakarta.servlet.
- java-no-print-stack-trace: Log exceptions instead of printStackTrace().
- js-no-bind-in-loop: Use arrow functions instead of .bind(this) in callbacks.
- js-no-body-parser: No new code depends on body-parser; reach for express.json().
- js-no-date-parse-ambiguous: Never parse locale-style date strings; use ISO 8601.
- js-no-delete-array: Do not delete array elements; use splice or filter.
- js-no-expo-app-loading: Do not import expo-app-loading; use expo-splash-screen.
- js-no-expo-permissions: Do not import expo-permissions; use the permission hooks of each Expo module.
- js-no-fs-exists: fs.exists is deprecated; use fs.access or fs.stat.
- js-no-global-this-window-name: Never store data in window.name.
- js-no-http-urls: Use https URLs in source code.
- js-no-iterator: Use Symbol.iterator, never __iterator__.
- js-no-octal-escape: No octal escape sequences in strings; use \u escapes.
- js-no-proxyquire: proxyquire is banned in this codebase. Use vi.mock instead.
- js-no-react-test-renderer: react-test-renderer is banned in this codebase. Use @testing-library/react instead.
- js-no-redux-thunk: Replace redux-thunk with RTK Query or createAsyncThunk from @reduxjs/toolkit.
- js-no-require-in-esm: This codebase is ESM: use import, not require.
- js-no-substr: Use slice instead of the deprecated substr.
- js-no-underscore: underscore is banned in this codebase. Use native array and object methods instead.
- js-number-isnan: Use Number.isNaN and Number.isFinite, never the global isNaN or isFinite.
- k8s-no-latest-image: Pin container images; never :latest.
- kt-no-android-os-asynctask: android.os.AsyncTask is banned in this codebase. Use coroutines instead.
- md-heading-no-punctuation: Headings do not end with punctuation (MD026).
- md-heading-single-space: Use one space after the # in headings (MD019).
- md-list-marker-space: One space after list markers (MD030).
- md-no-bare-urls: Wrap URLs in angle brackets or links (MD034).
- md-no-emphasis-line: In Markdown, never use a bold or italic line as a heading or tagline (MD036). Write a plain sentence or a real heading.
- md-no-html-comments-todo: No TODO comments hidden in Markdown; open an issue.
- naming-no-is-not: Name booleans positively (isVisible, not isNotHidden).
- naming-no-manager-classes: Avoid Manager, Helper and Util class names; name the responsibility.
- naming-py-private-single-underscore: Use a single underscore for private methods; double underscores mangle names.
- no-aws-s3-recursive-rm: Never delete S3 buckets or prefixes recursively.
- no-cargo-publish: Only the release workflow publishes crates.
- no-cat-dotenv: Never print .env files; they hold secrets.
- no-claude-attribution: No Claude or Anthropic attribution in commits, PRs or comments: no Co-Authored-By Claude, no "Generated with Claude Code", no Claude-Session or claude.ai session links.
- no-delete-main-branch: Never delete main, master or develop.
- no-em-dash: Never use em dashes. Use a comma, colon, parentheses or a full stop. In code that must match existing text, write \u2014.
- no-gh-issue-close-silent: Close issues only with a comment that says why.
- no-heroku-pg-reset: Never reset a Heroku database.
- no-mkfs: Never format disks.
- no-pod-trunk-push: Only the release workflow pushes pods.
- no-pr-assets-branch: Never push media to a pr-assets branch. Attach images and videos with gh pr create/edit/comment --attach <file>.
- no-redis-flushall: Never flush Redis.
- no-single-letter-names: Name variables for what they hold: no single-letter names except i, j and k (ESLint id-length).
- no-ssh-strict-host-off: Never turn off SSH host key checking.
- no-terraform-destroy: Never run terraform destroy.
- php-no-mysql-functions: mysql_* functions are removed; use PDO.
- playwright-no-wait-for-timeout: No waitForTimeout in Playwright; use auto-waiting assertions.
- podfile-no-unpinned: Pin CocoaPods dependencies to a version.
- pr-close-needs-reason: Close a PR only with a reason: gh pr close <n> --comment "<why, and what replaces it>".
- pr-no-checklist-boxes: No unchecked task boxes in PR bodies; finish the work or leave it out.
- pr-no-extra-sections: PR bodies have no sections beyond Problem, Approach, Scope, Tests and Screenshots. Put decisions for the user in chat.
- pr-sections: PR bodies use exactly these sections in order: ## Problem, ## Approach, ## Scope, ## Tests, ## Screenshots.
- py-no-bare-except: Catch a specific exception; never write a bare except:.
- py-no-blind-except: Do not catch Exception or BaseException without re-raising.
- py-no-imp: imp is banned in this codebase. Use importlib instead.
- py-no-os-path: Use pathlib instead of os.path.
- py-no-pickle-loads: Never unpickle untrusted data; use JSON.
- py-no-requests-without-timeout: Every requests call needs a timeout.
- py-no-sqlalchemy-text-fstring: Never build SQLAlchemy text() queries with f-strings; bind parameters.
- py-no-toml: toml is banned in this codebase. Use tomllib instead.
- pytest-no-unittest-assert: Use plain assert in pytest, not unittest assert methods.
- rails-no-default-scope: Do not use default_scope; use named scopes.
- react-no-index-key: Do not use the array index as a React key.
- react-no-legacy-lifecycles: Legacy lifecycle methods are banned; use hooks or the safe lifecycles.
- react-no-prop-types-ts: No propTypes in TypeScript components.
- react-no-string-refs: String refs are removed; use useRef or callback refs.
- react-no-unsafe-lifecycles: Do not use UNSAFE_ lifecycle methods.
- rspec-no-sleep: No sleep in specs; use time helpers or waiting matchers.
- ruby-no-coffee-rails: Do not import coffee-rails; use plain JavaScript.
- ruby-no-timeout-timeout: Timeout.timeout is unsafe; use library-level timeouts.
- secret-atlassian-token: Never commit a Atlassian API token. Read it from ATLASSIAN_API_TOKEN at runtime.
- secret-braintree-token: A Braintree production token belongs in the secret manager, never in the repo. Reference BRAINTREE_TOKEN instead.
- secret-circleci-token: Never commit a CircleCI personal token. Read it from CIRCLECI_TOKEN at runtime.
- secret-clojars-token: Never commit a Clojars deploy token. Read it from CLOJARS_TOKEN at runtime.
- secret-cloudflare-origin-ca: Do not paste a Cloudflare origin CA key anywhere in the repo or on GitHub; pass it through CF_ORIGIN_CA_KEY.
- secret-docker-auth: Do not paste a Docker registry auth anywhere in the repo or on GitHub; pass it through DOCKER_AUTH_CONFIG.
- secret-figma-token: A Figma personal access token belongs in the secret manager, never in the repo. Reference FIGMA_TOKEN instead.
- secret-flyio-token: Do not paste a Fly.io token anywhere in the repo or on GitHub; pass it through FLY_API_TOKEN.
- secret-github-pat: Do not paste a GitHub personal access token anywhere in the repo or on GitHub; pass it through GITHUB_TOKEN.
- secret-gitlab-trigger-token: Never commit a GitLab pipeline trigger token. Read it from GITLAB_TRIGGER_TOKEN at runtime.
- secret-huggingface-token: Never commit a Hugging Face token. Read it from HF_TOKEN at runtime.
- secret-postman-key: A Postman API key belongs in the secret manager, never in the repo. Reference POSTMAN_API_KEY instead.
- secret-prefect-key: Do not paste a Prefect API key anywhere in the repo or on GitHub; pass it through PREFECT_API_KEY.
- secret-readme-key: A ReadMe API key belongs in the secret manager, never in the repo. Reference README_API_KEY instead.
- secret-shopify-custom-app-token: A Shopify custom app token belongs in the secret manager, never in the repo. Reference SHOPIFY_APP_TOKEN instead.
- secret-slack-webhook: Never commit a Slack webhook URL. Read it from SLACK_WEBHOOK_URL at runtime.
- secret-square-secret: A Square application secret belongs in the secret manager, never in the repo. Reference SQUARE_APP_SECRET instead.
- sh-cd-or-exit: Guard cd with || exit (ShellCheck SC2164).
- sql-no-delete-without-where: DELETE statements need a WHERE clause.
- sql-no-implicit-join: Write explicit JOINs, not comma joins.
- sql-snake-case-tables: Table names are snake_case.
- swift-no-addressbook: Replace AddressBook with Contacts.
- swift-no-arbitrary-loads: Never enable NSAllowsArbitraryLoads; add a narrow exception domain.
- swift-no-force-try: No try!; handle the error or propagate it.
- swift-no-iuo: Avoid implicitly unwrapped optionals.
- swift-no-nslog: Use os.Logger instead of NSLog.
- swift-no-opengles: Do not import OpenGLES; use Metal.
- swiftui-no-edges-ignoring: edgesIgnoringSafeArea is deprecated; use ignoresSafeArea.
- swiftui-no-foreground-color: foregroundColor is deprecated; use foregroundStyle.
- swiftui-task-not-onappear-task: Use the .task modifier instead of starting a Task in onAppear.
- test-no-console-in-tests: No console.log in tests.
- tests-after-code: After code changes, run tests, typecheck or lint on their own (no pipe) before you finish. Never claim tests pass without a passing run.
- tf-no-public-db: Databases are never publicly accessible.
- tf-no-public-ip: Instances do not get public IPs; use a load balancer.
- ts-no-object-type: Do not use Object or Function as types; describe the shape.
- tsconfig-no-skip-lib-check-off: Never turn off noImplicitAny.
- tsconfig-strict: Keep strict mode on in tsconfig.
- vue-no-parent-access: Do not reach into $parent or $root; use props and emits.
- words-no-bleeding-edge: "cutting-edge" is banned in commit messages and PR text: name the version or feature.
- words-no-crazy: Do not write "crazy or insane" in commits, PRs or comments; say surprising or extreme.
- words-no-embark: Do not write "embark on" in commits, PRs or comments; say start.
- words-no-great-question: Cut "great question" from anything posted to GitHub; answer the question.
- words-no-important-to-note: Cut "it's worth noting" from anything posted to GitHub; state the point.
- words-no-kindly: "kindly" is banned in commit messages and PR text: say please or cut it.
- words-no-man-hours: "man-hours" is banned in commit messages and PR text: say person-hours or staff.
- words-no-next-level: "next-level" is banned in commit messages and PR text: say what improved.
- words-no-paradigm-shift: Cut "paradigm shift" from anything posted to GitHub; describe the change.
- words-no-please-note: "please note" is banned in commit messages and PR text: state the point.
- words-no-testament: Cut "a testament to" from anything posted to GitHub; state the fact it proves.
- writing-no-hype-words: No hype words in commits, PRs or comments: robust, seamless, comprehensive, leverage, utilize, delve.
